# 例外登记

例外是对具体规则的、有意的偏离。每条例外必须写明：偏离哪条规则、为什么、什么条件下撤销。

未登记的偏离视同违规；已登记的例外在被"顺手修复"前应先核对撤销条件是否已满足。

## EX-01 工具执行输出为 NUL 终止 char\*

- 偏离：全库文本一律长度限定视图（agent_string_view_t，无 NUL 依赖）的约定。
- 理由：工具输出的终点是 JSON writer 与模型可见文本，C 生态与调试习惯以 NUL 串为主；guard 的输出防护已按 char\* 语义设防（sink 逐块查 NUL）。
- 撤销条件：引入统一 text sink 管线且消费端全部视图化时回收。

## EX-02 policy_chain.c 为单回调而非链

- 偏离：命名暗示的"链式合并"语义（ALLOW/DENY/REQUIRE_CONFIRM 合并）未实现，当前是单点裁决。
- 理由：尚无第二个 policy 组合消费者，链式合并无需求支撑。
- 撤销条件：出现真实的组合需求时，要么实现链、要么改名。
