# ADR 0026: Session 文件 I/O 预制适配器

- 状态：提案
- 日期：2026-10-01
- 关联：[ADR 0016](0016-session-history-storage.md)、[ADR 0017](0017-runtime-portability.md)、[ADR 0023](0023-file-backed-memory-soul-skill.md)

## 背景

可选的 JSONL Session Storage Provider 已通过
`agent_session_jsonl_file_ops_t` 与文件系统解耦。它要求应用提供
`size/read/append/truncate/sync/remove/clear_all/count` 八项同步操作，并
自行映射长度视图形式的 Session ID。当前 Host 测试有一份 POSIX 文件回调
夹具，但不是面向产品的公共适配器。

每个应用重复编写路径映射、短读写处理、错误映射、尾部截断和目录枚举，
容易出错，也提高了 ESP-IDF、OpenVela/NuttX 和 RT-Thread 的接入成本。
但把这些文件操作放进 Core，或强迫所有目标使用文件系统，同样违背
轻量、可裁剪的目标。

## 方案比较

| 方案 | 优点 | 代价或风险 |
|---|---|---|
| 应用全部自行实现 file ops | Core 和后端最小 | 每个产品重复八项操作与安全细节，文档示例易被误当生产实现 |
| 每个平台复制一套 JSONL + 文件实现 | 平台接入直观 | 记录格式、恢复规则和修复逻辑易分叉，重复测试 |
| 共用 JSONL Provider + 可选通用文件适配器 | 保持领域语义唯一，复用文件操作 | 必须验证各文件系统的实际操作和耐久语义 |

## 决定

采用第三种方案。**首先提供一份可选的 POSIX 风格文件适配器**，填充现有
`agent_session_jsonl_file_ops_t`；在平台 API 或语义确实不兼容时，才增加
该平台的窄适配实现。不按平台目录对称原则复制同一份代码。

```text
Core Session 契约
    -> 可选 JSONL Session Storage Provider：turn 编码、提交、读取、尾部修复
        -> 可选文件适配器：安全文件名、精确 I/O、截断、同步、目录管理
            -> 应用挂载并配置的文件系统与介质
```

可选适配器不改变 Core 或 JSONL Provider 的接口。即使应用编入该适配器，
仍要显式配置 JSONL 缓冲、绑定 Storage，并选择用于 Session 的根目录。
没有文件系统的应用可继续使用 RAM 或自定义 Storage Provider。

### 适配器职责

- 将长度视图 Session ID 编码为**不可逃逸指定根目录**的文件名；拒绝空 ID、
  超长路径与不可表示的长度。`clear_all/count` 只处理本适配器命名空间内的
  文件，不触碰同目录中的 Memory、Soul、Skill 或其他产品文件。
- `read` 必须精确返回所需字节数，`append` 必须处理短写和中断；错误后允许
  留下部分尾部，由 JSONL Provider 尝试截断回滚。适配器不得在失败时伪造
  `AGENT_OK`，也不得自行跳过损坏的已终止 JSONL 记录。
- 将不存在与其他 I/O 错误区分，并检查偏移量、文件大小、路径容量及
  `off_t` 等平台表示范围；删除失败不能一律映射为“不存在”。
- `truncate` 要能修复未完成尾部，`sync` 要调用目标文件系统可用的同步
  操作。若目标不具备契约要求的操作，应拒绝该组合，而不是悄悄将其实现
  为空操作。同步调用成功也**不自动证明掉电后的数据耐久性**；具体保证
  取决于文件系统、介质和挂载配置，必须单独验证。
- 所有操作保持同步；共享适配器实例和 JSONL 状态时，调用方负责串行化。
  适配器可以使用底层文件系统的资源或分配器，但须声明内存、文件描述符
  和最坏延迟，不计入 Core 零 heap 的承诺。

### 应用与平台职责

应用负责选择分区、挂载文件系统、根目录、目录权限、容量配额、保留与清理
策略、加密、磨损预算和并发任务安排。预制适配器**不自动挂载、不格式化
介质、不创建私有分区**。这也避免库在启动失败时擅自擦除用户数据。

ESP-IDF VFS、NuttX 或 RT-Thread DFS 等环境可尝试编译并复用同一适配器，
但“有 POSIX 风格函数”不等于目标文件系统支持所有必要语义。每个目标至少
验证按偏移读、追加、截断、同步、目录枚举和错误码；不足之处由平台专属
实现或另一种 Storage Provider 解决。Host 通过只读测试不能替代真机验证。

`sync` 失败时，JSONL 的 `finish()` 可能已写入完整记录，只是无法确认其
耐久性；重试不能假定记录不存在。已终止但损坏的记录应报告解析错误。
现有 JSONL 后端只保存已结束的 turn，不能凭此宣称副作用 Tool 在掉电后
具备精确一次或完整意图日志语义。

## 适用范围与目录

建议先用一个可选目标承载通用实现，目录仅作实施建议，不预建空包：

```text
providers/storage/jsonl/        # 现有格式与 Session 事务，不含平台文件 API
ports/posix/storage/            # 可选的 JSONL file ops 适配器及契约测试
ports/espidf/storage/           # 仅当通用实现不足时加入专属代码
ports/openvela/storage/         # 同上
ports/rtthread/storage/         # 同上
```

构建系统只编译应用选用的适配器，不要求 Kconfig；平台集成可提供可选的
Kconfig/CMake 入口。单个产品可以同时构建不同后端或适配器，具体绑定由
应用初始化代码决定，而非全工程强制选一个全局文件系统。

NVS、键值 Flash 或缺少随机读/截断的原始介质**不得硬套** JSONL file ops。
它们可实现独立的 `agent_session_storage_t`，保留与 Core 相同的 Session
语义。PSRAM 热缓存也不是文件适配器的职责。

Memory、Soul 和 Skill 可以复用适配器底层的安全路径或文件访问代码，
但不能复用 Session 的 `agent_session_jsonl_file_ops_t` 作为统一领域接口：
Markdown 加载、记忆检索与完整 turn 事务的语义不同，见 ADR 0023。

## 实施顺序与验收

1. 从 Host 测试夹具提炼独立适配器；夹具只作行为参考，不原样提升为
   产品代码。先固定路径编码、命名空间、错误语义和调用方拥有的配置生命周期。
2. 用真实临时目录测试八项 file ops，并注入短写、短读、空间不足、偏移
   溢出、截断/同步/删除失败；复用现有 JSONL 端到端契约测试。
3. 在选定的 ESP-IDF、OpenVela/NuttX 和 RT-Thread 文件系统配置上逐项
   验证。若某平台不支持要求的语义，记录限制并改用专属实现或其他后端，
   不以 Host 测试通过宣称该平台已支持持久化。

发布适配器前还需验证：非本命名空间文件不会被 `clear_all` 删除；
重启后仅恢复完整记录；修复失败不会假报成功；文件系统资源和 I/O 峰值
在设备预算内。文件目录若可被不可信主体修改，产品必须额外处理符号链接
和路径替换等威胁，不能把文件名编码误认为完整访问控制。

本文只裁决可选预制 I/O 适配器的边界；不新增公共 C API，也不宣称上述
适配器已经实现。
